# v0.7 设计笔记：压缩策略在打转场景下的反向助燃

状态：**三条改进已全部实现**（2026-08-16 同日落地）：
1. `KEEP_RECENT_CHARS` 字符预算（compaction.py）；
2. 折叠留要点行（`_key_lines`：diff hunk 头 / FAIL 行 / 崩溃头）；
3. 大输出落盘 + `read_artifact` 句柄（tools.py 的 execute 漏斗）。
实测（cobra#1777 run）：压缩触发次数从 12+ 降到 4。
证据：`runs/20260816-013936`（testify#1785 能力边界
实验，deepseek-chat，零改动收场，49.4 万 token）。

## 现有设计的两个假设，与它们被打穿的现场

`compaction.py` 的取舍是"驱逐陈旧工具返回、保留 assistant 全部原话"，
理由（文件头第 3 条）："模型的结论比它读过的原始内容重要得多"。
这个假设在正常轨迹上成立，在**打转轨迹**上恰好反转：

1. **被驱逐的是证据**。模型拿到 `git diff v1.10.0..v1.11.0 -- mock/mock.go`
   （真凶所在），6 次新工具调用之后该返回被折叠。模型丢了证据但记得
   自己那句【错误结论】（"匹配逻辑没变"）——错误结论全程保留、反复重发，
   证据却要重新去取。轨迹里 `mock.go` 同一行段被重读 3-4 次，每次重读
   都是全价 token，读完不久再次被折叠。
2. **被保留的是废话**。T=0 打转时 assistant 输出几十遍同一段落，全部
   保留、每轮重发。压缩省下的字符远小于它守护的重复文本。
   （executor 的断路器已在 v0.7 落地：检测→截断→纠偏→两次无效放弃。
   它治打转本身；本笔记解决的是"证据被销毁"这一助燃剂。）

另一个不匹配：`COMPACT_AT_TOKENS = 12_000` 是按"历史 × 圈数"的成本模型
定的，方向正确；但 `KEEP_RECENT = 6` 按【条数】保留——6 条 `list_files`
和 6 条整段 diff 差一个数量级，保护窗口的实际大小完全不可控。

## 改进方向（按性价比排序）

1. **KEEP_RECENT 改按字符预算**：保留"最近 N 字符"的工具返回而不是
   "最近 6 条"。小改动，立刻让保护窗口可控。
2. **折叠留摘要行，不留纯占位符**：drop 前抽取结构性头部（diff 的
   hunk 头、read_file 的路径+行范围、测试输出的失败行），占位符从
   "需要请重读"变成"要点如下+重读指引"。确定性保持——纯文本抽取，
   不引入模型调用（沿用原设计哲学）。
3. **大输出落盘 + 句柄**：工具返回超阈值时写入 `run_dir/artifacts/`，
   给模型的返回是摘要+句柄，新工具 `read_artifact(handle, range)` 按需
   取窗口。上下文里永远只有模型主动要的部分；重读不再全价。
   （工程量最大，收益也最大——explorer 的"脏上下文不进来"哲学推广到
   所有工具返回。）
